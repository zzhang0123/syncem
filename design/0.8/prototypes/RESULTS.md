## 1. What was prototyped and how to run it

### 1.1 Scope

* **Core** (`core/`, 723 lines in 8 files). The pipeline `d = X~ S a` with `S = identity` (no column map): lattice and product table, kernels, averaged kernel with conditional laws and Legendre axes, jet columns, pairing of a measure with the table, prediction and direct integration. Tests: `tests/test_core.py`.
* **Six rule families** (`rules/<family>/`, tests in `tests/test_<family>_*.py`, results in `tests/<family>_results.json` or `tests/R*_results.json`).
  * R3a: the conditional-child node (`rules/R3a/`).
  * R5: azimuth-factor routes (i) to (iv) (`rules/R5/`).
  * beaming: pitch-Legendre columns, `Beaming` with cells on `mu`, parity masks and the half range (`rules/beaming/`).
  * fieldcells: field-scaling columns on `B` cells and the structural tie with energy columns (`rules/fieldcells/`).
  * partition: the identity `predict - direct = representation + outside_lattice` and provider checks (`rules/partition/`).
  * depth: closed-form phase weights, the depth-expansion threshold, screens and depth as a parent (`rules/depth/`).
* **Profile** (`profile/`). Eight hot paths timed (scripts `p1_*.py` to `p8_*.py`), with method-vs-method boundary tests in `profile/test_boundaries.py` (42 passed in 15 s). Results in `profile/results/*.json` and `*.log`. This step answers the question of a Rust direction (Sec. 6).

### 1.2 Environment

Machine: M3 Ultra, 28 cores, CPU, float64, JAX 0.10.0. Python: `<conda>/bin/python`. Most runs shared the machine with other agents (load average 60 to 220), so absolute wall times in the rule reports are upper bounds. Method ratios timed back to back are reliable.

### 1.3 Running

From this directory (`design/0.8/prototypes` in the syncem repository; `../../..` is the repository root):

```sh
PYTHONPATH=.:rules:../../.. python -m pytest -q tests
```

The `rules` entry is required: the R3a tests import `from R3a import ...`. Without it the three R3a files fail at collection (Sec. 1.5). With it the whole suite takes about 42 minutes on a quiet machine with the caches present. Fast subsets: `pytest tests/test_core.py -k "not A2 and not A3"` (30 s), `pytest tests/test_R3a_predict.py -m "not slow"`. The profile boundary tests run with `pytest profile/test_boundaries.py`. Several suites cache kernel evaluations on disk (`tests/_fieldcells_cache`, `rules/beaming/cache`, `rules/depth/cache.py`), so a second run is much faster than the first.

### 1.4 Core usage

`import core as C` enables float64 through syncem.

1. Table: `C.ProductTable.tensor({var: C.Cells...}, total=N)`. Rows are cells times the lower set, in graded lexicographic order. `table.row_cell` and `table.row_exp` describe every row. Each `Cells` keeps its own order, and `total` only caps the sum (Sec. 4, item 3).
2. Kernel: any object with `.n_ch` and `__call__(point) -> (I (n_ch,), P (n_ch,) complex)` written in `jnp`. Wrap it in `C.AveragedKernel(K, [(name, rule), ...], legendre={v: (L, nodes)}, fixed={...})`. A rule is a function of the point returning `(nodes, probs)`, so conditional laws are written directly and their derivatives enter the columns.
3. Columns: `C.build_columns(avg, table)` returns `{'I', 'P'}` of shape `(n_rows, n_ch, L...)`. Compilation is cached per `(avg, signature)`.
4. Moments: `C.pair(table, measure, w, legendre={v: L}, harmonic=bool)` with a `C.Measure` from `C.panel_measure` and `C.product`.
5. `C.predict(cols, table, moments, w, azimuth=c)` and `C.direct(avg, measure, table, azimuth=c)` return `(n_ch, 3)` [I, Q, U]. `C.representation_error(pred, ref)` gives max over channels and I, Q, U of `|dX| / I`.

```python
import numpy as np, core as C
tr = {"gamma": ("log", np.log(1e4), 2.0), "B": ("affine", 5.0, 2.0)}
K = C.PolynomialKernel.random(tr, degree=2, n_ch=4, seed=0)       # or core.paper.e1_kernel()
avg = C.AveragedKernel(K, [], legendre={})
tab = C.ProductTable.tensor({"gamma": C.Cells.log(300, 3e6, 4, order=2),
                             "B": C.Cells.linear(2, 8, 3, order=1)}, total=2)
cols = C.build_columns(avg, tab)
g = C.panel_measure("gamma", lambda x: x**-2.6, np.unique(np.r_[tab.lo[:, 0], tab.hi[:, 0]]), n=6)
b = C.panel_measure("B", lambda x: 0 * x + 1 / 6, [2, 4, 6, 8], n=4, chart="affine")
m = C.product(g, b)
w = C.reference_weights(tab)
a = C.pair(tab, m, w)
pred = C.predict(cols, tab, a, w, azimuth=0.4 * np.exp(0.5j))
ref = C.direct(avg, m, tab, azimuth=0.4 * np.exp(0.5j))
print(C.representation_error(pred, ref))                            # about 1e-15
```

Cost guide: one E1 averaged-kernel primal is about 0.24 s. The jet costs about `(1 + d_active)^levels` primals per cell. `direct` costs one primal per measure node, so keep direct measures small (6 nodes per panel suffice for exactness tests) or use the polynomial kernel. The E1 configuration is in `core/paper.py`.

### 2.1 Cross-cutting findings

* **Derivatives of laws that move with a celled parent must enter the columns.** Four families found the same failure when they do not. R3a: own `rule()` nodes times a cell indicator lose the edge flux. fieldcells: the per-node identity with nodes frozen at `B_b` is off by 1.2e-2 to 1.85. depth: frozen Delta nodes give zero `s > 0` columns. core: frozen nodes give 1.0e-1. Frozen nodes are admissible only with density reweighting on a fixed support (R3a, depth: equal to the jet to 7.5e-16).
* **Truncation acts on the product with any factor in the basis.** R5 routes (ii) and (iv) truncate `c K_P`. R3a truncates `u^r g(u)`. Averaging the child (R3a) or moving `c` to the moment side (R5) changes which function is truncated.
* **Boundary validation.** No family has a numeric dispatch threshold in the core. The dispatches are preconditions (field scaling, half range, mask, depth threshold, frozen nodes). Every family evaluated both methods directly at extreme parameters, and the depth family found the one misplaced threshold (`tau_max h <= 1`).

## 6. Profile summary and the Rust question

| Hot path | Measured | Bound by | Native candidate |
|---|---|---|---|
| 1. S1 field-average table | 0.32 to 0.34 s per field node (NumPy), 99.6 per cent in quadrature. S0 plus lookups: about 6 ms per node | compiled NumPy, one core, and an algorithm that redoes the quadrature per field node | No. S0/S1 gives 60 to 150 times in NumPy |
| 2. Column build, stack vs jet | stack 0.17 / 0.25 s (N = 2 / 4, 19 cells). Jet 10.4 / 70.7 s | jet: re-evaluation of F, G by quadrature at every node, already on 15 to 18 cores | Unlikely above 3 times. A smooth tabulated F, G in JAX is the larger lever |
| 3. Free-moment fit | 0.15 to 0.21 us (shared noise, JAX). 13.6 to 51 us per pixel on all cores | LAPACK on small matrices | No |
| 4. NNLS 111 x 272 | 2.96 ms serial, 0.51 ms per spectrum in a pinned pool | compiled active set | No |
| 5. Family fit | 2.39 ms `trf`, 60 us batched JAX LM | Python overhead inside `trf` | No. Batching in JAX removes the overhead |
| 6. Ray sightlines | basis route 3.7 ms per ray, direct 2.5 to 98 s | scatter-adds and complex exponentials | No |
| 7. High-order harmonic host route | 2.2 to 2.9 ms per point (3 channels) | about 90 per cent per-call overhead, 10 per cent SciPy `jv` | Plausible, but NumPy vectorisation reaches the same Bessel floor first |
| 8. Interval certification | 1.30 to 1.43 s per call under load | pure-Python `mpmath` (4.0 million calls, backend 'python') | Yes if routine, through an existing library (`gmpy2`, `python-flint`/Arb) before any new Rust crate |

**Recommendation.** Keep SyncEM in JAX, NumPy and SciPy for 0.8 and 0.9. No profiled hot path is interpreter-bound in a way that a Rust rewrite would fix better than an algorithmic change or batching in the current stack. The largest measured factors are algorithmic:

* S1 by an S0 table in `ln x` plus lookups: 60 to 150 times per field node.
* Tabulated F, G for forward kernels: 45 times, 1.1e-11 of I.
* Basis-route pairing for rays: 670 times against tabulated direct, 2.6e4 times against quadrature direct.
* Batched JAX LM for family fits: 40 times against `trf`.
* Per-pixel SVD on all cores: 13 times against one core.

The jet compile cost (Sec. 4, item 10) is a JAX compile cost, and a Rust port would not change it. Native code is plausible later on two paths. Interval certification can take `gmpy2` (no code change, 2 to 5 times, estimate) or `python-flint`/Arb (10 to 100 times, estimate). The harmonic host driver should first be vectorised in NumPy, and Rust is worth revisiting only if a vectorised driver still exceeds about 0.3 ms per channel point.

**Proposed design-file changes for this question** (not applied). A new decision row in Sec. 8 or 9: no native code in 0.8 and 0.9, with named seams (host-only kernels, the certification arithmetic backend, the harmonic host driver), `gmpy2` or `python-flint` in the certification extra, and the revisit trigger above. Sec. 6.4 and 8.6: batched family fits as jitted `vmap` LM with `trf` as oracle, and NNLS on the host with a process pool and BLAS pinned to one thread (`OMP_NUM_THREADS=1`, `VECLIB_MAXIMUM_THREADS=1`). Sec. 8.2, 8.3 and 8.7: S0 plus S1 lookups in place of the per-node S1 quadrature, the measured jet costs, and the smooth tabulated F, G as the candidate for the jet primal. Ray: the direct reference uses tabulated F, G, and the basis route is the production path.

Method-vs-method boundary tests of the profile (`profile/test_boundaries.py`, 42 passed in 15 s): S1 by S0 lookups against study quadrature, 0.1 to 100 uG, orders 0 to 6, at most 3.7e-8 OK. Tabulated F, G against 128-node quadrature from x = 1e-13 to the table end and both sides of the end: 1e-13 to 5.1e-10 OK. The syncem harmonic switch (direct line sum against corrected integral) at gamma 5 to 3000 and candidate counts 0.5, 1 and 2 times the direct limit: 3.2e-14 to 7.9e-8 OK. Off the emission cone (mu = 0.3, eta = 0.2, gamma >= 300) every harmonic line underflows to zero, so a harmonic benchmark there is vacuous. The tests were rerun on the cone.

## 7. What remains unverified

### 7.1 Not prototyped

* The column map (parity masks as an engine feature, `Beaming` merges, `spin0_from`), units, the lattice key, the error ledger, the `Lattice` wrapper and the front door.
* Fits (free-moment, penalised, NNLS, family, bilinear, basis-parametric) beyond the profile timings. Rank rules (T9, T18), cache keys (T14), caching and serialisation.
* The harmonic kernel route and the kernel switch (T1), the `x_min` adapter (T3), field-average defaults per law (T4), the cut-off rule (T7), samples and `PointMasses` at cell edges (T8), `Ray` other than the profile timing.
* A production `Beaming` capability, a factor hook on the spin-2 block and a phase-free kernel option (Sec. 4, item 7).
* Depth outside the total degree in a production lattice (Sec. 3.8, item 3).

### 7.2 Measured incompletely or not reproduced

* r2-03: the I column ratio 0.118 was not reproduced (0.067 in the small-x regime). The SPEC does not give its cell, channel or normalisation.
* r2-02: the even-mask figure of 11 per cent was not reproduced (16.1 per cent for `eta ~ U[0, 1/2]`). The eta law of r2-02 is unknown.
* r3-23: first-screen numbers for 0.408 to 23 GHz channels at fixed B were not re-measured.
* The reference-density estimate of `outside_lattice` was not measured for a spectrum harder than gamma^-2.6, where it may fall below the source share.
* R3a order 6 under nested `jacfwd` and beaming N = 8 under the jet were stopped unfinished.
* The S0/S1 split agrees with the study quadrature to 3.7e-8 at order 6. Its effect on a fit was not measured.
* Knock-on edits of Sec. 3.8 (G15 counts and pass status, row 29) follow from the depth rule but were not computed.

### 7.3 Not measured in the profile

JAX sharding of the jet across cells (the machine was loaded beyond its core count), a JAX port of the full stack provider, the harmonic JAX cell (SPEC: 6.5 s per cell), a jet over a smooth tabulated kernel, and the `gmpy2` and `python-flint` speed-ups (estimates only).

### 7.4 Timing caveat

Every rule-family wall time was taken at load averages 60 to 220 on 28 cores and is inflated 3 to 8 times against an unloaded machine. The Sec. 5 values from the core, the first profile runs and the fieldcells solo runs saw lighter load. Ratios timed back to back hold.
